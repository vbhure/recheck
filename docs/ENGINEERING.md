# Engineering record

What was found wrong, how, and what changed. Every code fix has a regression
test; RG-07 and RG-08 were documentation fixes and have none. The
regulatory-engine, final-pass and deep-review tables name the tests, and the
red team's are in `tests/test_rt_*.py`.

## How defects were found

1. **Building against the regulation text** — Table I, 4.25 and 4.26 worked examples.
2. **Attacking the running product** — corrupt state, oversized input, hostile answers.
3. **A hostile judging panel** — eight independent reviewers, each attacking one question (Strands usage, is the AI needed, is the human load-bearing, clarity, every claim, architecture theatre, impact, regulatory correctness), with every finding independently re-verified before it was acted on.
4. **Reviewing the fixes** — a test-suite rewrite, mutation-tested by a separate reviewer; a fixture and lexicon rework, checked value by value against the eCFR text.
5. **An adversarial red team** against the release candidate, then a final regression pass over the merged fixes, then a verification of that pass.
6. **A deep review** of the next release candidate (12705f8) in nine areas. Each finding was reproduced and fixed on its own branch with a regression test; in seven of the areas an independent verifier attacked the fixes again before the branches were merged.

## When a person is asked

| Defect | Evidence | Fix |
|---|---|---|
| **Questions that could not change anything** | 3 of 4 sweep questions gave the same rating under every answer; a lone side-less knee interrupted | materiality: enumerate every answer through the engine; ask only if final degrees differ; show the possible results |

## Red team

Five attackers went at the release candidate (af714cb), one each on arithmetic, the model boundary, the human loop, files and state, and secrets and network. Each finding was reproduced independently before it was assigned. There were **53 findings**: 6 P0, 17 P1, 18 P2 and 12 P3. Some are one defect seen from two angles.

Four agents fixed them, each in a separate part of the code. A separate reviewer then attacked each fix again. The review found one new P1 and one data-loss regression introduced by the first fixes, plus leftover gaps. A second round fixed those. A final regression pass then attacked the merged code where the fixes met each other; its findings are listed below and were fixed too, as were those of a verification of that pass. There are **421 regression tests** in `tests/test_rt_*.py` (30 of them, in `test_rt_verify.py`, from the verification). Each one fails on the code before its fix, except the controls, which say so.

### What held

- **Arithmetic.** 3,060 generated letters were run through the CLI, and 58,325 engine fact sets were checked against an independent oracle. No complete case had a wrong degree, and no rating list was misread. 192 cases stopped for an answer. Resumed with the true facts, 187 gave the oracle's degree. Four ended UNDETERMINED because of ARITH-F6 (fixed above), and one was a genuinely open case.
- **Model boundary.** Every malformed payload was rejected after exactly one call. That covered extra fields, NaN or 1e308 confidences, lookalike group names, tool input that was not an object, 41 items, and prompt-injection names. The one-turn limit held.
- **Network and credentials.** The zero-model path made no connection or DNS attempts. Planted credentials never appeared in any output or file, apart from SECRETS-F1. Re-checked on the merged code with `--debug` and planted AWS and Anthropic keys: none appeared.
- **Human loop.** All 31 hostile `--answer` strings were rejected, and each question stayed open. A fact the letter states could not be overridden. No figure was ever computed while a question was open. The tampered Strands sessions tried were refused without producing a figure. The deep review then found one that was not (HITL-1: an answer written into the session replaced the reviewer's typed one, NO DISCREPANCY at exit 0). Resume, show and sweep now accept a session only in the shape assess leaves it: one interrupt, raised by assess for this case, with extract and classify completed and nothing else to re-run.
- **Wording.** No report says a decision is wrong or in error, that anything is owed, or that anyone should appeal. The words appear only in negations: the disclaimer ("not a claims or appeals service", "not a conclusion that the decision is wrong"), the verdict and triage ("not a finding of error"), and the 4.26(d) note that prior evaluations "were not in error". The exception is a Python exception name and message (PdfStreamError, JSONDecodeError) given as the reason a letter or a case file could not be read.

### Known residuals

- **A confident wrong classification is used.** The floor and the veto stop uncertain answers and a "none" for a limb or nerve word. A wrong "upper" at confidence 0.9 still gets through. The verdict then names the AI classification it rests on.
- **Text inside a table row's name is part of the name.** A row "Cubital tunnel syndrome Jane Q Veteran ...... 10%" is read with the whole name and sent to the model with it, unless it carries a label, a date or a long number.
- **A staged rating under two different names, or as two numbered table rows, reads as two ratings.** For example, "left knee strain, 20%" followed later by "limitation of flexion of the left knee, increased to 30%". Text alone cannot tell this apart from two separately rated conditions of the same knee. Identical table rows are kept on purpose (two separately rated scars), so a staged rating listed as two rows with the same name is counted twice.
- **A link in wording the parser does not list can lend a limb and side.** "Hypertension, with right knee injury" is read as a right lower-extremity rating. "with" is not treated as a link, because names such as "Degenerative arthritis with limitation of motion, left knee" use it for the rated condition itself. With the listed link phrases, the opening words (by, after, since, subsequent to, from, during, while) and the both-sides rule, none of the link wordings in the deep review's generator was misread.
- **A staged combined evaluation in its own sentence after a heading is read as its first stage.** "... is 20 percent until February 28, 2026. Thereafter it is 30 percent." is read as a stated 20%. The same stages in one sentence are refused.
- **A case file edited consistently is not caught.** Loading checks each fact against its name, its recorded owner and the letter's values in the trace. A file whose conditions, percentages, trace entries and ratings are all edited together, or whose trace entry for an edited value is deleted, still reports those false values. Only re-reading the letter would catch it. So does a stated value edited onto a letter that could not be read: `show` prints it above COULD NOT READ THE LETTER.
- **Free text in a hand-edited trace is printed as written.** The verdict, the figures and the values read from the letter are re-derived or checked, but the details, rules and evidence of other trace entries are not, so an edited case.json can add text to the printed trace. Control characters in it are shown escaped.
- **Some letters cannot be finished by answering.** Five compensable names outside the lexicon, with no classifier, make 16,807 combinations. That letter ends UNDETERMINED without a question.
- **Letters near the work budget are slow.** The slowest letter under the budget took 10 to 15 s to audit on a loaded machine.
- **4.26(d) under M21-1's lenient reading.** In 6 of 126,572 generated settled five-rating letters, 4.26(d) decides only if an unknown side is "both" and the lenient M21-1 reading of a both-sides evaluation applies. The report uses the strict reading and gives these letters no decision-period caveat. The final degree is unaffected.
- **Hidden text in a PDF.** Only text drawn in an invisible render mode (3 or 7) is refused as hidden. Text under a full-page image, white-on-white text, and text outside the page or clipped away are read as letter text.
- **Provider SDK logs.** Under `--debug`, Recheck masks credential-shaped text it can see, but not everything the provider SDKs log, so treat a `--debug` log as sensitive. Preflight refuses a Bedrock VPC endpoint or gateway.
- **Not exercised on POSIX.** The lock's delete-before-release order was worked out on paper and tested with a monkeypatch on Windows, not on a POSIX machine. SEC-4's discard of a linked case directory was tested with a Windows junction; its symlink branch has not been run. The letter's path is stored as given, so a resume from another working directory cannot check the letter's digest and goes ahead anyway.
- **The parser refuses some ordinary wording.** Hard-wrapped all-caps prose, a year inside a condition name, or a percentage in an unrelated paragraph refuses the whole letter. So do spaced dot leaders in a table (". . . .", EXTRACT-9) and a CAPS "COMBINED EVALUATION FOR COMPENSATION:" wrapped before its percentage inside a prose letter; on one generator seed, on the extraction branch, these were about 200 and 64 of 2,500 random letters. That fails closed, but it is a letter a reviewer checks by hand.
- **A case directory that is a link to a deleted directory cannot be re-audited** (XC-3). `audit` and `sweep`, even with `--fresh`, exit 3 with FileExistsError, because they discard only a case whose case.json exists. Nothing outside the store is touched; the link has to be removed by hand, and planting it needs write access to the store.
- **An interrupted save leaves files behind** (STATE-6). A process killed while saving leaves a `.case.*.tmp` file in the case directory and a `<case>.lock` file in the store.
- **Minor.** A custom Model's exception class name can appear in the note. The provider line (`describe()`) prints `RECHECK_OLLAMA_HOST`, password masked, for Bedrock and Anthropic too, which never use it (SEC-5). A run stopped part-way by Ctrl+C gets a triage row with no command to continue it, and its report's provenance can mislead (CLI-6). A directory passed as a letter, preflight failures printed to stdout and pypdf warnings on stderr have unclear messages (CLI-7). An interrupt response for another case re-asks the question and adds a second question entry to the trace; no genuine flow sends one.
